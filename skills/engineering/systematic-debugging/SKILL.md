# 系统化调试

> 核心原则：**先复现，再定位，后修复**。禁止"看起来像是这里的问题，改了试试"式的盲改。

## 触发场景

- 用户报告 Bug："xx 功能不对"、"报错了"、"为什么一直失败"
- 测试/线上出现异常堆栈、错误日志
- 行为与预期不符但无明显报错（静默错误）

---

## 阶段 1：复现（Reproduce）

**目标是稳定复现，不是立刻找原因。**

### 1.1 收集事实

| 信息 | 来源 |
|------|------|
| 错误现象/报错信息 | 用户描述、日志、堆栈 |
| 触发路径 | 用户操作步骤、输入数据 |
| 影响范围 | 必现 or 偶现？全部用户 or 特定条件？ |
| 变化点 | 什么时候开始出现的？最近改过什么？ |

### 1.2 最小化复现

- 找到触发问题的**最短路径**和**最小输入**
- 剥离无关步骤，确认每一步都是必要的
- 偶现问题：记录出现/不出现的条件差异（数据、时序、环境）

### 1.3 复现判定

| 结果 | 处理 |
|------|------|
| ✅ 稳定复现 | 进入阶段 2 |
| ⚠️ 偶现 | 提出 2-3 个假设解释偶现条件，逐个验证；无法复现则收集更多日志再试 |
| ❌ 无法复现 | 明确告知用户现状与已尝试路径，请求补充信息，**不进入猜测性修复** |

---

## 阶段 2：定位（Locate）

**用二分法缩小范围，用证据说话。**

### 2.1 确定问题层次

```
用户输入 → 参数校验 → 业务逻辑 → 数据访问 → 外部依赖 → 返回呈现
```

先判断问题在哪一层：
- 输入就是错的？（数据问题）
- 逻辑处理错了？（代码问题）
- 依赖返回异常？（环境问题）

### 2.2 二分缩小范围

- 调用链长 → 在中间点插入日志/断点，判断前半段还是后半段出错
- 最近引入 → `git bisect` 定位引入 commit
- 部分数据出错 → 对比正常数据与异常数据的差异字段

### 2.3 定位输出

定位完成的标志是能用一句话说清：

> 「在 X 条件下，执行到 Y 位置时，因为 Z，导致实际值 A 与期望值 B 不符」

说不清这句话 = 未定位完成，继续缩小范围。

---

## 阶段 3：根因（Root Cause）

**区分"直接原因"与"根本原因"。**

| 层次 | 示例 |
|------|------|
| 表象 | 页面白屏 |
| 直接原因 | `list.map()` 时 list 为 null |
| 根本原因 | 接口异常时未返回兜底空数组，且前端未做空值防御 |

**追问链条**：对每个原因再问一次"为什么会这样"，直到问到可修复的设计/代码缺陷为止（通常 2-3 层）。

**常见根因模式**：

- 空值未防御（数据源可能不返回该字段）
- 异步时序（响应晚于组件销毁 / 后发先至）
- 隐式类型转换（`"0"` vs `0`、`==` vs `===`）
- 状态共享污染（全局单例/缓存被意外修改）
- 环境差异（时区、平台 API 行为、版本差异）

---

## 阶段 4：修复（Fix）

### 修复原则

1. **修根因不修表象**：禁止用 try-catch 吞掉、判空绕过等方式掩盖根本问题
2. **最小改动**：只改与根因直接相关的代码，不顺手重构
3. **防御范围正确**：防御加在责任方（谁的数据谁兜底），而不是每个调用点都判空
4. **考虑同类问题**：搜索同模式代码，确认是否有一样问题的兄弟代码

### 修复前确认

向用户说明（内部调试可省略）：
- 根因是什么
- 准备怎么修
- 影响范围

---

## 阶段 5：验证（Verify）

**修复 ≠ 问题解决，验证通过才算。**

```
□ 1. 原始复现路径：问题不再出现
□ 2. 边界场景：触发问题的极端输入也正常
□ 3. 回归检查：修改点的其他调用方未受影响
□ 4. 同类排查：同模式代码是否需要一并修复
```

## 输出格式

```markdown
## 🐛 调试报告

**现象**：一句话描述
**复现路径**：步骤 1 → 2 → 3
**根因**：在 X 条件下，Y 处因为 Z，导致 A ≠ B
**修复**：改动文件与方式（最小改动说明）
**验证**：
- ✅ 原始路径已修复
- ✅ 边界场景通过
- ✅ 回归无影响
**预防建议**：（可选）如何避免同类问题再次出现
```

## 禁止事项

- ❌ **禁止未复现就修复**：无法复现时明确说明，不猜测性改代码
- ❌ **禁止盲改试错**：连续改 2 处以上还说不清为什么，说明定位不充分
- ❌ **禁止表象修复**：吞异常、强行判空绕过、加 sleep 等掩盖手段
- ❌ **禁止未验证就宣称修复**：必须回走复现路径确认
